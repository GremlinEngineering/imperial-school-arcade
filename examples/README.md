# Примеры Python

Два самостоятельных модуля показывают, как связать редакционные материалы с изменениями данных. Они используют стандартную библиотеку Python 3.10 и новее.

| Пример | Что делает |
| --- | --- |
| [Два взгляда на одну игру](view_revision.py) | Находит пару недельной и личной карточки одной версии, вычисляет основание совместного текста |
| [Изменение состава серии](series_revision.py) | Сравнивает участников, учитывает личный статус и прежние обозначения серии, объясняет причину изменения |

## Два взгляда на игру

`pairs` получает объекты с полями `key`, `retroachievements_id`, `in_profile` и `platform`. Недельный выпуск задаётся ключом вида `2026-10-W43`. Он связывается с личной карточкой по RA ID и платформе.

`signature` дополнительно использует `description` обоих объектов. Подпись меняется вместе с исходными текстами и идентичностью пары. Примеры объектов с `SimpleNamespace` находятся в [проверках](test_principles.py).

Для текстового этапа рядом приведены [входные данные](view-input.json), [форма ответа](view-output.example.json) и [промпт синтеза](../prompts/05-context/01-view-synthesis.md).

## Изменение состава серии

`membership_state` получает список серий с их участниками и создаёт сравнимое состояние. Аргумент `previous` позволяет привести прежние обозначения к известным текущим идентичностям.

`membership_signature` вычисляет подпись состояния. `membership_change_reason` показывает содержательную причину пересмотра: появился участник, исчез участник или изменился личный статус. Примеры минимальных данных и ожидаемого поведения приведены в [проверках](test_principles.py).

## Запуск проверок

Проверки самостоятельных примеров запускаются из корня архива:

```bash
python3 -m unittest discover -s examples -p 'test_*.py' -v
```

Проверки используют демонстрационные данные и стандартную библиотеку Python. Они показывают поведение сопоставления карточек и сравнения состава серии.
