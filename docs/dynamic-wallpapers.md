# Спецификация динамической темы

Динамические обои — законченные статичные кадры, меняющиеся по данным и событиям. Тема содержит рисунки и JSON-правила. Сервер выбирает слои и собирает изображение для конкретного устройства; приложение получает готовый JPEG и описание сборки.

## Состав темы

Коллекция объявляется как `type: dynamic`. Каждый профиль устройства содержит свои размеры, каталог `assets` и `rules`. `schema_version: "0.2"` включает базовую и бытовую фазы; прежний контракт 0.1 сохраняет свою совместимость.

| Элемент | Значение |
| --- | --- |
| `asset` | Идентификатор подготовленного рисунка |
| `layers[].id` | Канал композиции, а не обязательный отдельный предмет |
| `order` | Целочисленный порядок наложения; меньшие значения ниже |
| `opacity` | Непрозрачность от 0 до 1 |
| `when` | Точное условие выбора |
| `phase` | `base` или `life`; при отсутствии — `base` |

Один слой может содержать несколько предметов и их взаимные перекрытия. Сервер управляет целым слоем. Для разных устройств используются отдельные рисунки в их собственном разрешении. Неуказанный слой пуст; отсутствие входного значения не разрешает подставить случайный объект.

Отдельные рисунки устройства могут показывать собственную сцену или адаптацию общего сюжета. Художественный подход не меняет значение входных кодов. Он выражается в подготовленных рисунках и правилах профиля. Телефонный профиль не обязан повторять настольное число каналов, предметов или вариантов; описанное для одного устройства не становится обязательным для всей коллекции. См. [подходы к экранам](wallpapers.md).

## Условия

Категориальные состояния передаются кодами: сезон, время суток, фаза Луны, погодная группа и игровые признаки. Числа находятся рядом — например, температура, давление, видимость и положение Солнца. Их реестр задаёт единицы и ограничения контракта. Порог в теме — художественный выбор, не универсальная граница погоды.

Поддерживаются `=`, `!=`, `<`, `<=`, `>`, `>=`, а также логические комбинации предусмотренной схемой. Отсутствующее числовое значение не участвует как ноль. Базовые правила не используют бытовой час. Конфликтующие правила не разрешаются догадкой о наиболее красивом варианте.

## Наложение

Выбранные полноразмерные RGBA накладываются на фон по `order`. Альфа рисунка и `opacity` участвуют вместе. Для переднего края чаши, рамы или перил может потребоваться отдельный ближний слой: один объект способен занимать несколько уровней глубины.

Все правила с одинаковыми входами и одинаковым состоянием автомата должны давать одинаковый рецепт. Число возможных кадров определяется сочетаниями совместимых правил. Произведение числа вариантов — лишь верхняя оценка для независимых каналов; исключения, совместные условия и календарные связи уменьшают число достижимых состояний.

## Бытовая фаза

Сначала выбирается базовый рецепт без бытовых слоёв. Он сравнивается с предыдущей успешной сборкой этой области темы и устройства. Изменением считаются состав слоёв, исходник, порядок или непрозрачность. Колебание неиспользуемого числового поля само по себе не является сменой изображения.

| Условие | `derived.life_slot` |
| --- | --- |
| Первая сборка | `null` |
| Базовый рецепт изменился | `null`, блокировка до конца местного часа |
| Текущий час уже заблокирован | `null` |
| База стабильна, час не заблокирован | Местный час от 0 до 23 |

Пропущенные сценки не накапливаются. Возвращение базы к старому варианту в заблокированном часу не снимает блокировку. При `null` бытовые правила не выбираются. Смена бытовой позы не отменяет действующий игровой признак. Полные схемы — в [реестре форматов](formats.md), доставка — в [динамическом API](dynamic-api.md).

## Точное разрешение каналов

Внутри каждой фазы совпавшие правила не могут выбрать два слоя с одним id. Сначала формируется base. Выбранный life-слой с тем же id целиком заменяет базовый: asset, order и opacity берутся из life; отсутствующая opacity означает 1, а не наследование. В итоговом рецепте order уникален. Коллизия является ошибкой темы, а не основанием выбрать последнее правило.

Базовый ключ учитывает выбранные исходники и их SHA-256, размеры, идентичность слоёв и рендерер. Замена рисунка под прежним именем тоже меняет базу. Область автомата включает тему, устройство, источник, ревизию места/мира и часовой пояс. При смене области прежнее состояние не переносится. Повтор идентичного запроса переиспользует сохранённое решение; устаревший момент не продвигает автомат назад. Состояние фиксируется вместе с успешной сборкой; доставка — отдельный этап.
