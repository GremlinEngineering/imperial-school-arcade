# Динамический кадр, JSON и архивы

Сборка изображения и доставка результата — отдельные действия. Публикация использует уже подготовленный комплект, а клиент читает готовый результат. Новая картинка не считается доступной только по факту появления записи в художественной матрице.

## Ресурсы

База: `https://games.oopssre.ru/assets/arcade/views/`. `T` — ID темы, `D` — устройство из её каталога.

| Материал | Путь |
| --- | --- |
| Текущий JPEG | `dynamic/T/devices/D/current.jpg` |
| Превью | `dynamic/T/devices/D/current-preview.jpg` |
| Текущий JSON | `dynamic/T/devices/D/current.json` |
| История состояний | `dynamic/T/devices/D/states.zip` |
| Исходники устройства | `downloads/theme-T-D.zip` |

Для «Затонувшей чайной» профиль `desktop_3456x2234` использует собственный кадр 3456 × 2234. Другие профили читаются из объявленного каталога; клиент не должен угадывать их наличие по этой строке.

## Что содержит JSON

Оболочка текущего кадра описывает тему, устройство, момент, готовое изображение и превью. `inputs` сохраняет данные выбора, `recipe` — выбранные слои, `asset_sha256` — использованные исходники. Контракт 0.2 добавляет `life` с решением автомата. `image.sha256` относится к готовому JPEG, а не к архиву темы.

Запись позволяет объяснить, почему выбран кадр, и воспроизвести его при наличии подходящих исходников. Воспроизведение использует сохранённые входы и рецепт; новые часы и свежий прогноз не должны менять прежнюю сцену. Побайтное равенство JPEG дополнительно зависит от объявленной реализации рендерера и JPEG-библиотеки.

## История и обновление темы

На сервере хранится один текущий растровый кадр устройства с превью. `states.zip` содержит JSON-историю, а не накопленный альбом всех JPEG. История группируется по дням и контекстам; её полноту следует определять по фактическому содержимому, а не ожидать по одному кадру на каждый час.

Архив исходников относится к устройству. Тема обновляется под тем же адресом; старые версии рисунков не обязаны сохраняться. Поэтому старый JSON воспроизводим только пока у читателя есть именно использованные исходники. Скачанный ранее архив уже содержит их и не нуждается в обязательных сетевых ссылках на все прежние рисунки.

## Поведение клиента

Проверить ID темы и устройства, размер, срок актуальности и контрольные суммы. При изменившемся кадре получить новые байты. Погодный источник и бытовая сцена уже учтены сервером: повторно выбирать их в клиенте не требуется. При временном сбое приложение сохраняет применённые обои по своей политике, но не объявляет их новым состоянием.
