# Wallpaper applications and device capabilities

Imperial School Views applications use site collections and supported archives. Display format, weather source and artwork are separate selections. Capabilities depend on application release; available artwork follows the published catalogue.

The macOS client supports ordinary and weather collections, daily wallpapers, calendar policies, downloads and ZIP imports. Monitors can share a profile or use individual settings. Its viewer offers zoom, fullscreen and slideshows; the screen saver uses prepared images. A user-selected Open-Meteo city belongs to that source. Dynamic themes arrive as ready JPEGs, with no client-side layer composition.

Android offers collection selection, viewing and wallpaper use on supported phone screens. Network policy, downloaded content and source/city choice belong to application settings. Home/lock screen behaviour, independent selections and background updates depend on the release and Android restrictions. Local dynamic-image history records received frames; it does not promise a server archive of all JPEGs.

The Windows client belongs to the same collection system. Additional capabilities must be established for its release rather than copied from macOS or Android descriptions. Clients select declared formats, verify bytes, and refresh schedules after world/location revisions. A previously applied image may remain in place with its original status.

Sources and dedicated instructions: [Imperial School Views](https://github.com/GremlinEngineering/imperial-school-views). Contracts: [weather](weather-api.md) and [dynamic delivery](dynamic-api.md).

## Software and device themes

The [software page](https://games.oopssre.ru/software.html) groups installers, sources and available device themes. When enabled, footer navigation also exposes applications and themes; the music area links its application. Device-theme packages have their own id, title, device, version and usage terms. Their ZIPs are not application installers.

Repository links belong to release metadata. Download and source-code actions serve separate purposes and appear together when a repository is declared. A missing repository URL must not be guessed from an installer filename.
